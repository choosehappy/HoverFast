# HoverFast — Agent Instructions

## What It Is

GPU-only nuclear segmentation tool for whole-slide pathology images (WSIs). PyTorch-based MSU-Net variant with a CLI entry point `HoverFast` → `hoverfast.main:main`.

## Setup & Install

- **Environment**: Conda (base env). Use `source /opt/conda/etc/profile.d/conda.sh && conda activate base` before running anything. Python interpreter is `/opt/conda/bin/python`.
- **Python >= 3.9** required. CUDA ≥ 12.1.0 mandatory — `torch.cuda.init()` runs at import time in `hoverfast/main.py:7`, so any code path that imports `main` will fail without a GPU.
- Install: `pip install .` from repo root (reads `requirements.txt`). Dockerfile uses `uv pip install . --system`.
- Docker image: `petroslk/hoverfast:latest`. Container working dir is `/app`; source lives at `/HoverFast/`.

## CLI Modes

| Subcommand | Purpose | Key flags |
|---|---|---|
| `infer_wsi` | Segment nuclei in WSI files (`.svs`) | positional: slide folder(s), `-m` model, `-o` output dir, `-b` mask dir, `-st he\|ihc_dab`, `-g` GPU batch size, `-d` SpatiaLite DB output |
| `infer_roi` | Segment nuclei in ROI images (`*.png`) | same as above plus `-r` memory batch, `-w` border width, `-c` overlay color |
| `train` | Train from pytable datasets | positional: dataset name, `-p` dataset path, `-b` batch size, `-e` epochs, `-d` depth, `-w` width |

Default model: `./hoverfast_crosstissue_best_model.safetensors`. Model files are `.safetensors` or `.pth`.

## Testing

- Run all tests: `pytest -vv` (from repo root).
- Tests use `subprocess.getstatusoutput()` to invoke the `HoverFast` CLI — the package must be installed on `PATH`.
- `tests/conftest.py` downloads a small Aperio `.svs` test image (`CMU-1.svs`) on first run (slow first invocation, cached after).
- **GPU required for inference tests** (`test_wsi_inference`, `test_roi_inference`). Installation-only tests in `test_installation.py` are CLI smoke checks that still require GPU (importing the CLI triggers `torch.cuda.init()`).
- `tests/unit/` directory is empty — no unit tests exist.
- Bug: `test_train_help_works()` in `test_installation.py` calls `infer_roi -h` instead of `train -h`.

## Code Quality Tools

Ruff and mypy are configured in `pyproject.toml` but are **not wired into CI** (no `.github/workflows/`). They can be run manually:
- Lint/format: `ruff check hoverfast/` / `ruff format --check hoverfast/`
- Type-check: `mypy hoverfast/` (many modules have errors disabled; effectively only a small subset is type-checked)

## Architecture Notes

- Single package: `hoverfast/`. Core model is `HoverFast` class in `hoverfast/hoverfast.py` (MSU-Net conv blocks, dual up-path for main + auxiliary outputs).
- WSI I/O via `openslide-python`; output is JSON-GZ or SpatiaLite DB (`-d` flag on `infer_wsi`).
- Training data format: HDF5 pytables (`.pytable`) generated by a separate data-generation container.
- No CI workflows, no pre-commit config, no Makefile for the project itself (only docs/).

## Gotchas

- `.gitignore` excludes `*.svs`, `build/`, `*.sqlite`, `ajtest/`, `*.gz`, and log files.
- `config.ini` at repo root is a sample training data-generation config, not consumed by the CLI directly.
- `-g` (GPU batch size) auto-calculates from available VRAM: roughly `VRAM_GB // 2 - 1`. Each +1 in batch costs ~2 GB VRAM for the pretrained model.
